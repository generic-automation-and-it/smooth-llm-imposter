# AGENTS.md — Routing Optimization (HLD 017)

## TL;DR

Strategy interface + coordinator for HLD 017 message optimization. Read [LADR-08](../../../../../docs/hlds/017-message-optimizer/ladrs/LADR-08-parallel-strategies.md).

## Non-Negotiables

- **NativeAOT: no assembly scanning.** Strategies registered explicitly in `DependencyInjection.AddApplication`.
- **Overlap rule:** two edits claiming the same JSON pointer → forward the original body.
- **Byte-preserving merge:** top-level patches use the raw `DecisionJson.ReplaceTopLevel` writer; nested patches use `JsonPointerPatcher` text spans. Never re-serialise the whole body (NFR-01).
- **Failure isolation:** a throwing/cancelled/timed-out branch contributes no edit; others still apply. Caller cancellation propagates.
- **One harness tag source.** `HarnessSpans` is shared by HLD 014 extraction and `HumanSpanExtractor`; never duplicate the tag arrays in a consumer.
- **Captured sessions only.** `MessageChecksumCache` refuses derived or missing session identities and never includes the inbound model in its scope.
- **Validation is deterministic and absolute.** Any changed or added protected element rejects the rewrite; only one targeted retry is allowed, then the original is forwarded (LADR-04).
- **The message is data, never a prompt.** The optimizer user turn is the message between `<message_to_rewrite>` delimiters and nothing else; the instructions forbid answering, fulfilling or obeying it. Any instruction change bumps `MessageOptimizationStrategy.InstructionRevision`, which is part of the cache version, so old-prompt rewrites are never replayed.
- **One local-LLM call in flight, process-wide.** Every optimizer call (first try and the validation retry) takes `OptimizerAdmissionGate` after the circuit check, so an open circuit never waits; the gate takes the shared `LocalLlmSlot` that every tool-filter and message-gate decision also takes, so no optimizer call overlaps any other optimizer or decision call, whatever endpoint or model (HLD 015 LADR-05, amended 2026-10-29).
- **Catalog names are conditional.** A protected tool/MCP name is required in the rewrite only when the original mentions it; never reject a rewrite for an unrelated catalog entry.

## Key Behaviors

- **Checksum cache:** SHA-256 over the original human text plus the optimizer version; the first stored value is final; a hit replays bytes and makes no model call. A whole scope drops only after its sliding TTL (default/max 120 h) and there is no scope or entry cap.
- **Per-section circuits:** the gate and optimizer each own a `SectionCircuitBreaker`; one service failure opens that section only, an open section makes zero calls, and a cooldown admits one trial. Caller cancellation, local gate waits and invalid answers never trip. Open gate continues to the optimizer; open optimizer forwards the original.
- **Optimizer admission (WT-24):** the wait is bounded by `LLM_MESSAGES_TIMEOUT` and runs on the injected `TimeProvider`; the deadline timer is created only when the gate is taken. A timeout is the typed `OptimizerAdmissionTimeoutException`: the strategy logs one Warning (model, endpoint, seconds; no text), forwards the original and caches it, records nothing on the circuit and abandons a trial admission so the next request gets the trial. Caller cancellation while waiting propagates, makes no call, caches nothing and releases nothing it did not take. The gate holds no collection of its own any more, so `ProcessMemoryRegistrationTests` no longer lists it. Optimizer retries default to one (`LLM_MESSAGES_MAX_ATTEMPTS` 2) after `LLM_MESSAGES_RETRY_DELAY_SECONDS` (default 5, 0–60), all inside the held slot.
- **Per-request budget (WT-25, Open item 7):** `OptimizationBudget` bounds the gate and optimizer time of one request by `LlmMessagesOptions.BudgetSeconds` (`LLM_MESSAGES_BUDGET_SECONDS`, default 30, validated 1–600 while enabled). Its deadline runs on the injected `TimeProvider` and starts lazily at the first model call, so a replay-only request creates no timer. Calls get a token linked to the caller's; on expiry the in-flight gate call, optimizer call or admission wait is cancelled, and the existing caller-cancellation paths treat it as cancellation, so no circuit records anything and a trial is abandoned. `IsExhausted` (deadline fired, caller not cancelled) tells the two apart: caller cancellation still propagates, budget expiry does not. Finished rewrites keep their patches; the in-flight and every later uncached segment are cached and forwarded as the original (never left uncached, or the next request would rewrite them and break NFR-01). One Information line per such request carries only the budget, unprocessed and candidate counts. Tests use a deadline-only manual clock (`AdmissionClock(signalledDueTime)` in L0, `BudgetClock` in L2), never sleeps.
- **Rewrite validation:** `Validate` compares protected tokens (code, links, paths, numbers, versions, env vars, negations, commands, mentions, identifiers), rejects introduced tokens, harness tags and supplied instruction lines, and compares heading/list/fence structure. `ValidateWithRetryAsync` forwards the original after one failed retry; failed-element values are for the retry prompt, never for logs (NFR-04).
- **Content retention:** `Validate` rejects a rewrite keeping less than 60% of the original's content words (`content:kept k of n content words`), which is what catches an answer, refusal, obeyed injection, translation or over-summary — they are shorter and add no protected element. Content words are lower-cased `[\p{L}\p{N}]+` runs with a trailing plural `s` folded; the stop list holds function words plus the pleasantries and hedges the optimizer is told to remove, so removing filler never counts against a rewrite. Adding a real content word to the stop list weakens the check; an original with no content words skips it. A reply wrapped in the delimiters is unwrapped by stripping only the newline `Delimit` adds on each side, never all whitespace, because a human segment's leading or trailing space joins it to a harness span; any other delimiter in a rewrite is `added-delimiter`.
- **Dollar and slash commands share one rule:** both match hyphenated names (`$imposter-who`, `/git-commit-push`), so swapping the part after a hyphen is a changed element. The corpus found the dollar pattern stopping at the hyphen. Fenced-block content is protected only because the single-backtick code-span pattern matches between the fence backticks; a test pins that, and changing the pattern needs an explicit fence-content check. **Negations are counted, other classes are presence-based:** each negation word must occur exactly as often as in the original, because dropping one of "do not A and do not B" leaves a `not` behind and inverts the second instruction, and adding one inverts a clause too; numbers, paths and the rest are not counted because a rewrite may merge repeats without changing meaning, and a rewrite that merges two negations is discarded (the original wins on doubt).
- **Strategy flow:** candidates are user messages in array order, handled sequentially and gated once per message. A message whose human segments are all cached replays without a model call; a gate decline records every uncached human segment as the original; a gate failure or an open gate continues to the optimizer; optimizer failure or an open optimizer records the original; a discarded rewrite records the original. Within a message, each human segment shorter than `MinChars` skips both models and is not cached; a switch message, assistant/system turn, tool-result turn and non-text block are skipped. Only text pointers are patched; harness spans, serialized signed model output (a balanced JSON value with a string `signature` property, or an unclosed one running to the end of the message, pasted into user text) and non-text blocks stay byte-identical.
- **Per-route opt-out:** `ProviderOptions.OptimizeMessages` (`<PROVIDER>_OPTIMIZE_MESSAGES`) reaches the strategy as `OptimizationRequest.Provider`; only `false` skips, so `null`/`true`/no route all optimize. The check lives in `MessageOptimizationStrategy`, not the coordinator, so the tool strategy still contributes on an opted-out route. The option is a new scalar and so rides the HLD 011 plumbing rule (post-configure suffix, `ProviderOptionsCloner`, both admin DTOs, `ProviderCatalog`); the Host must pass `plan.Decision.Provider` or the flag is inert, and only the L2 opt-out test catches that. Nothing sets it automatically; GitHub Copilot now bills tokens through AI credits (per-request billing only on legacy annual plans), so Copilot routes are not opted out by default.
- **Inbound scope:** the strategy skips Responses inbound requests even when the Host has downgraded them to a Chat body (Open item 4). `OptimizationRequest.InboundPath` carries the pre-transform path; the effective `Path` alone cannot distinguish a downgraded Responses request from a real Chat request.
- **Transport resolution:** `LlmMessagesOptions` is resolved from the post-configured `ImposterOptions.LlmMessages` by `LlmMessagesOptionsSetup`. That setup is load-bearing: without it the client sees an empty `BaseUrl`/`Model`/`ApiKey` and the cache and optimizer circuit ignore the operator's TTL and cooldown.
- **Log hygiene:** the strategy and coordinator log exception types (with section/model/endpoint), never the exception object, because a `JsonException` can carry message or reply text (NFR-04).
- **Gate transport:** `MessageGate` posts one choice question through the shared decision client under the `Imposter:DecisionsMessages` section, so it uses that section's resolved profile (`DECISIONS_MESSAGES_*`, then shared `DECISIONS_*`, then the built-in default; HLD 015 LADR-05), and its `Model`/`Endpoint` circuit log fields read the same profile. The profile never inherits `DECISIONS_TOOLS_*`: a deployment that sets only `DECISIONS_TOOLS_*` transport sends the gate to the built-in default, and `Decisions/MessageGateTransportWarning` logs one startup Warning for exactly that case (a hosted service, because `ImposterOptions` is materialized twice at startup and a post-configure warning printed twice).

## Test References

- **L0** `Application.UnitTest/Routing/Optimization` — span extraction (excluded spans, byte reassembly, unclosed openers, signed model output: string-aware, outermost, disjoint, unsigned or non-string `signature` stays human, truncated tail, stray prose bracket and prose-quoted key stay human), checksum cache (first value, version, scope, TTL, sessionless), rewrite validation (accepting/rejecting fixture per protected class, introduced elements, structure, length, echo, one-retry policy), message gate probability, strategy flow (patches, replay, minimum, one gate per multi-segment message, decline/positive/failure/open/bypass, downgraded Responses skip, bridged Messages→Chat, retry, switch, tool-result, cancellation, type-only failure logs), `LlmMessagesOptionsSetupTests` (structured and conventional `LLM_MESSAGES_*` precedence), and per-section circuits (trip class, cooldown, trial close/reopen, endpoint/log shape, integration with both strategy calls).
- **L0** `Application.UnitTest/Routing/Optimization/MessageRewriteFidelityCorpusTests` — NFR-02 corpus: Claude Code and Codex-shaped messages with clean and altering rewrites; the validator must accept every clean one, reject every altering one for the intended failure kind, and a second independent check (whitespace tokens, character shape, whole-fence comparison) must flag nothing the validator accepted. Answer, refusal, obeyed-injection, other-language and over-summary rewrites must be rejected as `content`; the second check flags them by the share of the rewrite's words borrowed from the original and the share of letters kept. A self-check requires that second check to flag every altering rewrite so it cannot pass vacuously. Deterministic: it measures the validator, not a live model.
- **L0** `Application.UnitTest/Routing/Optimization/OptimizerAdmissionGateTests` + strategy admission cases — a held optimizer admission blocks the shared slot and a slot held by a decision call queues the optimizer, timeout on the manual `AdmissionClock` takes no slot, caller cancellation releases nothing; strategy: timeout forwards and caches the original without opening the circuit, cancellation makes no call, a timed-out trial is left to the next request. `AdmissionClock.TimerCreated` is the deterministic "a caller is queued" signal (no sleeps).
- **L2** `Host.IntegrationTest/MessageOptimizerAdmissionTests` — two concurrent requests through the Host with a blocking optimizer stub: the second request queues at admission (signalled by its deadline timer) rather than reaching the optimizer, and max in-flight stays 1.
- **L0** strategy budget cases — expiry mid optimizer call (finished rewrite kept, rest cached as original, one Information line, both circuits still closed, replay), mid gate call, mid admission wait (budget, not the contention Warning), and no timer for a replay-only request; validator 1–600 boundaries; structured and conventional binding.
- **L2** `Host.IntegrationTest/MessageOptimizerBudgetTests` — a stalled optimizer and a clock that fires only the budget deadline: the in-flight call is cancelled, the upstream receives the finished rewrite and the rest as written, the next turn replays every earlier message byte for byte, and gate and optimizer are still called for the new message.
- **L0** `Infrastructure.UnitTest/Clients/Optimizer` — request shape, bearer auth, retry status policy, caller cancellation, and the full-response attempt timeout (a stalled body must not outlive `TimeoutSeconds`).
- **L2** `Host.IntegrationTest/MessageOptimizerCachePrefixStabilityTests` — NFR-01: a multi-turn Anthropic replay (harness block, tool rounds, gate decline, unusable optimizer answer, rewrite discarded by validation, gate failure, optimizer failure, both circuits open, trial close) asserts every earlier message is forwarded with identical raw bytes and that call counts match the script; separate cases cover the sliding TTL via a manual clock and that missing or credential-derived sessions are never cached. An unusable optimizer answer is used on purpose: a failure that opens the circuit is masked by the open-circuit path recording the same original, so only a non-tripping failure isolates the on-failure record.
- **L2** `Host.IntegrationTest/MessageOptimizerIntegrationTests` — an opted-out provider forwards the message with zero gate/optimizer calls (the only test that fails if the Host stops passing the route), and `ProviderConfigAdminIntegrationTests` round-trips the flag through GET → PUT → GET.
- **L2** `Host.IntegrationTest/MessageOptimizerIntegrationTests` — the real optimizer client through the coordinator seam rewrites Chat and Anthropic messages with the configured `LLM_MESSAGES_*` destination, a captured session replays without new model calls, and a downgraded `/responses` request makes no gate or optimizer call.
- **L2** `Host.IntegrationTest/MessageOptimizerFailureCostTests` — NFR-03 over the real decision and optimizer clients (only the transports are stubbed, a manual clock drives the cooldown, one attempt per call): the four failure combinations (down and transport-throw) forward a valid body with an unchanged caller response; per section, one exhausted call opens the circuit, requests then make zero transport calls for it while the other section is still asked, one trial runs after the cooldown and a failed trial reopens it; one Error line carries section, model, endpoint, cause and retry time with no message text at Information and above; the tool branch or the whole message stage failing alone leaves the other's edit applied; caller cancellation mid-call opens no circuit. The log capture replaces `ILoggerFactory`, because `UseSerilog` ignores extra providers.
- **L2** `Host.IntegrationTest/MessageOptimizerEgressTests` — NFR-04 over a Claude Code-shaped turn (system prompt, tools, reminders, hook output, skill command block, image, tool result, caller credential, each with a sentinel): the gate state is exactly each candidate's human text, the optimizer user message is exactly that text between the `<message_to_rewrite>` delimiters, and nothing else reaches either model; optimizer requests hold only `model`/`messages`/`stream` (instructions plus one plain-text user message), gate requests only `model`/`questions`/`state`; two candidates are four separate requests (gate, optimizer, gate, optimizer) with at most one in flight; no log line at Trace carries message text except the routing layer's opt-in Debug inbound dump (pinned as the one known exception); a disabled feature makes zero requests.
